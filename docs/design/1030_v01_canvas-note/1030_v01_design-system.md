## 1. 목적과 범위

- 다루는 것: 디자인 원칙, 토큰(색·글꼴·간격·모서리·그림자·움직임), 종이 템플릿, 컴포넌트, 질문 상태별 모양, 접근성, 쓰지 않는 것
- 다루지 않는 것: 두 번 톡 판정과 범위 알고리즘(`1030_v01_handwriting-question-recognition.md`)
- 루트 `DESIGN.md`는 이 문서의 요약이다. 둘이 어긋나면 작업을 멈추고 확인한다(`CLAUDE.md` §8).

## 2. 배경

사용자는 「진짜 노트」를 원한다. 종이 질감, 괘선, 잉크, 제본처럼 손에 익은 물건의 모양을 빌리고, 화면 장치(도구 막대, 꼬리표)는 그 물건 옆에 조용히 둔다. Nodi의 노드·카드 디자인은 쓰지 않는다(D-006).

시각 방향은 세 시안을 만들었고 **시안 A**로 정했다(D-014). B의 모눈과 C의 무지는 종이 템플릿으로 가져온다. B·C 값은 비교용으로 §4에 남긴다.

## 3. 설계

### 3.1 원칙

1. **필기가 먼저다.** 화면의 주인공은 종이와 내 글씨다. 장치는 작고 낮은 대비로, 종이 밖 책상 위에 둔다.
2. **AI 글은 출처가 보인다.** AI 글은 인쇄체와 전용 잉크색으로 쓰고, 색 말고 표시를 하나 더 둔다(도장·쪽지·번호). AI 잉크색은 사용자 펜 색상표에 넣지 않는다(D-011).
3. **진짜 물건처럼 움직인다.** 형광펜은 띠로 칠해지고, 답은 줄에 맞춰 써지고, 밀린 필기는 줄 단위로 내려간다. 떠다니는 카드나 연결선은 없다.
4. **애매하면 필기로 남긴다.** 시스템 표시(범위, 꼬리표)는 언제든 취소할 수 있게 하고, 사용자 획은 함부로 바꾸지 않는다.

### 3.9 움직임

| Token | Value | 쓰는 곳 |
|-------|-------|---------|
| `--dur-fast` | 120ms | 꼬리표 나타남·사라짐 |
| `--dur-row` | 150ms | 답 자리 만들기의 줄 이동 |
| `--ease-paper` | `cubic-bezier(.2,.7,.2,1)` | 줄 이동 |

- 답 글자는 스트리밍으로 받은 만큼 바로 보인다. 일부러 느리게 타자 치는 효과는 넣지 않는다.
- 펜을 고르면 트레이에서 펜이 올라온다(200ms). 이 외에 저절로 움직이는 장식은 없다.
- `prefers-reduced-motion`이면 이동 없이 바로 바뀌고, 진행 점은 멈춘 채 보인다.

### 3.10 접근성

- 대비: AI 글은 종이 위에서 7:1 이상(A 약 9.6:1), UI 글자는 4.5:1 이상, 손잡이·점선 같은 그래픽은 3:1 이상(손잡이 약 3.7:1). 종이에 인쇄된 장식(No., Date, 괘선)은 장식이라 예외다.
- 출처를 색만으로 알리지 않는다: 도장(A), 쪽지와 「AI 답」 라벨(B), 각주 번호(C).
- 터치 대상은 44×44 이상. 펜 트레이 펜은 보이는 크기보다 터치 영역을 넓힌다.
- 왼손잡이 모드: 꼬리표를 범위 왼쪽에 두고, 세로 도구 막대를 반대편으로 옮기고, 손바닥 무시 영역을 바꾼다.
- 화면 낭독: `AnswerBlock`은 `role="note"`와 「AI 답」 라벨로 텍스트를 낭독한다. 질문 범위는 인식 텍스트를 라벨로 준다.
- 확대: AI 글은 쪽 확대와 함께 커지고, 쪽 폭에 맞췄을 때 14px 이상이다.
- 어두운 화면: v01은 종이 은유를 지키려고 밝은 종이만 쓴다. 시안 C처럼 책상만 어둡게 하는 방법은 남은 질문.

### 3.11 쓰지 않는 것 (D-006)

- 흰 바탕 점 격자 무한 캔버스
- 왼쪽 강조 막대가 있는 카드, 카드 오버레이
- 블록 사이 곡선 연결선
- 연두·올리브 계열 강조색
- 아래쪽 채팅 입력창, 왼쪽 아이콘 세로 내비게이션
- AI 글을 손글씨 글꼴로 쓰기

## 4. 대안과 선택 이유

## 5. 검증 방법

- 대비: §3.2의 글자·그래픽 조합을 WCAG 대비 계산기로 확인해 이 문서에 값을 적는다.
- 토큰만 쓰기: 화면 코드에서 HEX(`#[0-9a-fA-F]{3,8}`)와 Tailwind 임의 값(`-\[`)을 찾는 lint를 CI에 넣는다. 토큰 정의 파일만 예외다.
- 시각 회귀: Playwright로 주요 상태(§3.8)의 화면을 찍어 비교한다.
