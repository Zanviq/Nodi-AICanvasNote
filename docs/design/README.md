# design

전반적인 설계와 설계 변경을 기록하는 공간이다. 결정 로그, 설계 묶음, 변경 설계서를 둔다.

## 용도

| 종류 | 무엇 | 위치 |
|------|------|------|
| 결정 로그 | 프로젝트에서 내린 결정을 번호(`D-001`…)로 쌓는 단일 파일. **모든 문서 중 우선순위가 가장 높다.** | `1030_DL_decision-log.md` |
| 설계 묶음 | 특정 버전의 전체 설계 문서 묶음 | `MMDD_v{NN}_{이름}/` |
| 변경 설계서 | 상위 설계와 다르게 구현해야 할 때 먼저 쓰는 문서. 해당 항목에 한해 기존 설계보다 우선한다 | `MMDD_{기준 커밋 7자리}_change-{변경-이름}.md` |

- 여기에 두지 않는 것: 작업 하나만의 작은 설계(`docs/work/`), PR 설명(`docs/PR/`), 조사 보고서(`docs/report/`)
- 우선순위: 결정 로그 → 변경 설계서(해당 항목) → 최신 설계 묶음 → `DESIGN.md` → `docs/work/` → PR·report. (루트 `CLAUDE.md` 3.2절)

## 현재 문서

| Path | 내용 |
|------|------|
| `1030_DL_decision-log.md` | 결정 로그 |
| `1030_v01_canvas-note/` | 설계 묶음 v01 — `README.md`(목차)부터 읽는다 |
| `1030_v01_canvas-note/mockups/` | HTML UI 시안 |

## 이름 규칙

| 대상 | 형식 | 예 |
|------|------|-----|
| 결정 로그 | `MMDD_DL_decision-log.md` (파일 하나만 유지, 날짜는 처음 만든 날로 고정) | `1030_DL_decision-log.md` |
| 설계 묶음 폴더 | `MMDD_v{NN}_{이름}/` | `1030_v01_canvas-note/` |
| 묶음 안 문서 | `MMDD_v{NN}_{문서-이름}.md` | `1030_v01_design-system.md` |
| 묶음 목차 | `README.md` | `1030_v01_canvas-note/README.md` |
| 묶음 안 시안 | `mockups/MMDD_v{NN}_mockup-{이름}.html` | `mockups/1030_v01_mockup-a-school-ruled.html` |
| 변경 설계서 | `MMDD_{기준 커밋 7자리}_change-{변경-이름}.md` | `1112_a1b2c3d_change-answer-placement.md` |

- `{이름}`은 소문자 영문 kebab-case 권장, 한글 허용, 공백 금지.
- 설계를 크게 다시 쓰면 기존 묶음을 고치지 않고 새 버전 묶음(`v02`)을 만든다. 새 묶음 README에 이전 버전과 달라진 점을 적는다.

## 작성 규칙

- **결정 로그**
  - 새 결정은 맨 아래에 다음 번호로 추가한다. 번호는 다시 쓰지 않는다.
  - 결정을 뒤집으면 기존 항목을 지우지 않고 상태를 `대체됨(D-XXX)`으로 바꾸고 새 항목을 추가한다.
  - 상태: `제안`(사용자 확정 전) / `확정` / `대체됨(D-XXX)` / `폐기`.
  - `제안` 상태 결정에 기대는 작업은 시작 전에 사용자에게 확인한다.
- **설계 묶음**
  - 묶음 `README.md`에 문서 목록과 각 문서의 절 목차를 둔다. 읽는 사람은 목차로 필요한 절만 찾아 읽는다.
  - 문서 안의 절에는 번호를 붙인다. 다른 문서는 「문서 이름 §절 번호」로 가리킨다.
  - `mockups/`처럼 묶음 안에 하위 폴더를 만들면 그 폴더에도 `README.md`(용도·이름 규칙·목록)를 둔다.
- **변경 설계서**
  - 상위 설계와 다르게 구현해야 하면 코드보다 먼저 쓴다.
  - 합의(1인 개발에서는 사용자 확인)를 받은 뒤 상태를 `합의됨`으로 바꾸고, 결정 로그에 항목을 추가한다.
  - 합의된 변경 설계서는 그 문서가 다루는 항목에 한해 기존 설계보다 우선한다.
- 디자인 시스템 문서를 고치면 같은 PR에서 루트 `DESIGN.md`도 맞춘다. (루트 `CLAUDE.md` 8절)

## 문서 양식

아래를 그대로 복사해 쓴다. 해당 없는 절은 지우지 말고 「해당 없음」이라고 쓴다.

### 결정 로그 파일

```markdown
# 결정 로그

모든 문서 중 우선순위가 가장 높다. 새 결정은 맨 아래에 추가한다.

## 목록

| ID | Title | Status | Date |
|----|-------|--------|------|
| D-001 | {제목} | {제안/확정/대체됨(D-XXX)/폐기} | YYYY-MM-DD |

## 결정

(아래 「결정 항목」 양식을 이어 붙인다)
```

### 결정 항목

```markdown
### D-{번호 3자리}. {결정 제목}

| 항목 | 내용 |
|------|------|
| 상태 | {제안/확정/대체됨(D-XXX)/폐기} |
| 날짜 | YYYY-MM-DD |
| 결정자 | {GitHub ID 또는 이름} |
| 관련 문서 | `{경로}` §{절} |

- **맥락**: {왜 이 결정이 필요했는지}
- **결정**: {무엇을 정했는지. 확인 가능한 문장으로}
- **이유**: {왜 이것을 골랐는지}
- **고려한 대안**: {대안과 버린 이유}
- **영향**: {바뀌는 문서·코드·디자인}
```

### 설계 묶음 README (목차)

```markdown
# 설계 묶음 v{NN}: {이름}

| 항목 | 내용 |
|------|------|
| 작성일 | YYYY-MM-DD |
| 작성자 | {GitHub ID} |
| 기준 커밋 | `{7자리}` 또는 해당 없음 |
| 상태 | {작성 중/확정/대체됨(v{NN})} |
| 이전 버전 | `{경로}` 또는 해당 없음 |

## 1. 개요

{이 묶음이 다루는 범위를 한두 문단으로 쓴다.}

## 2. 이전 버전과 달라진 점

- {없으면 「해당 없음」}

## 3. 문서 목록과 목차

| File | 내용 | 주요 절 |
|------|------|---------|
| `MMDD_v{NN}_{문서-이름}.md` | {한 줄 요약} | §1 {절}, §2 {절}, … |

## 4. 관련 결정

- D-XXX {제목}
```

- 다른 설계 문서: {…}
