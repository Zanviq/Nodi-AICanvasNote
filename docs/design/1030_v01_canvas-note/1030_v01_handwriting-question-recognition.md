## 1. 목적과 범위

- 다루는 것
  - 펜 두 번 톡을 일반 필기와 구분하는 규칙 (§3.3)
  - 톡 한 자리에서 질문 문장 하나의 범위를 찾는 알고리즘 (§3.4–3.8)
  - 범위 표시와 수정, 질문 문맥 만들기 (§3.9–3.10)
  - 답을 넣는 자리 만들기와 이어 질문 (§3.11–3.12)
  - 다른 기능과의 충돌 처리, 성능 예산, 연구용 기록 (§3.13–3.15)
  - 논문용 평가 방법 (§5)
- 다루지 않는 것
  - 펜 획을 그리는 렌더링과 필기감 튜닝 (제품 개요 §3.6)
  - 답변 생성 모델의 프롬프트 세부 문구 (구현 작업 설계에서 정한다)
  - 화면 색과 모양 (`1030_v01_design-system.md`)

## 2. 배경

이 앱은 노트 앱이라 대부분은 그냥 필기다. 질문도 따로 표시하지 않고 필기 사이에 쓴다. 사용자가 그중 한 문장 위를 펜으로 두 번 톡 하면, 앱은 다음을 해야 한다.

1. 그 두 번 톡이 마침표나 쌍점이 아니라 질문 제스처라는 것을 안다.
2. 어디부터 어디까지가 그 문장인지 정한다. 손글씨 노트는 마침표가 자주 빠지고, 문장이 줄 중간에서 시작하거나 다음 줄로 넘어가며, 목록 기호와 들여쓰기가 섞여 있다.
3. 그 문장만 읽어 질문으로 보내고, 답을 바로 아래에 쓴다.

2번의 정확도가 사용 경험을 좌우한다. 범위가 짧으면 질문이 잘리고, 길면 엉뚱한 문장이 섞인다. 이 문서는 2번을 획 기하와 글자 인식을 섞은 2단계 알고리즘으로 푼다(D-009).

Nodi는 펜으로 쓴 질문 전체를 이미지로 그려 Gemini가 읽었다. 이번에는 필기와 질문이 섞여 있으므로 「어느 획이 질문인가」를 먼저 풀어야 한다는 점이 다르다.

## 3. 설계

### 3.1 용어와 데이터

| Term | 뜻 |
|------|-----|
| `Stroke` | 펜을 대고 뗄 때까지의 점 열. 점마다 `x, y, pressure, tiltX, tiltY, t` |
| `GlyphCluster` | 가로로 겹치는 획 묶음. 대략 글자 하나 또는 받침까지 포함한 음절 |
| `Word` | 단어 간격(τw)으로 나뉜 `GlyphCluster` 묶음 |
| `Segment` | 같은 줄에서 큰 간격(τs)으로 나뉜 `Word` 묶음. 한 줄에 왼쪽 필기와 오른쪽 메모가 따로 있으면 두 `Segment` |
| `InkLine` | 한 줄에 놓인 `Segment` 목록과 기준선 |
| `Block` | 1단계가 고른 후보 줄 덩어리 |
| `Token` | 인식 결과를 띄어쓰기로 나눈 단위. 획 묶음과 연결된다 |
| `QuestionSpan` | 최종으로 고른 문장. 시작·끝 `Token`과 획 목록 |
| `AnswerBlock` | AI 답 객체. 획이 아니다 |
| `FollowUpSlot` | 이어 질문을 쓰는 칸 |
| `Thread` | 첫 질문에서 이어진 질문·답 묶음 |

단위 규칙

- 제스처 기준은 **화면 위 실제 거리(mm)와 시간**으로 잡는다. 확대 배율과 상관없이 손의 정밀도는 같기 때문이다.
- 배치 기준은 **글자 높이 h 또는 괘선 간격 p의 배수**로 잡는다. 글씨 크기와 종이에 상관없이 같은 비율로 동작한다.
- h는 그 쪽 획들의 「몸통 높이」(한 획의 y값 15–85 백분위 구간) 중앙값으로 추정한다. 표본이 20획 미만이면 괘선 종이는 0.55p, 무지는 그 노트의 이전 값으로 둔다.

### 3.2 처리 흐름

```text
펜 톡 ─► [제스처 판정 §3.3] ─ 아님 ─► 필기 점으로 확정
             │ 질문 제스처
             ▼
   [획 전처리 §3.4] → [줄 구성 §3.5]
             ▼
   [1단계: 후보 덩어리 §3.6] ──► 점선으로 후보 범위 표시 (≤0.1초)
             ▼
   [인식 §3.7] (덩어리의 줄만 읽음)
             ▼
   [2단계: 문장 경계 점수 §3.8] ──► 형광펜으로 문장 범위 표시 (≈1초)
             ▼
   [질문 문맥 만들기 §3.10] → 답 생성(스트리밍)
             ▼
   [답 자리 만들기 §3.11] → 줄 위에 답 쓰기
```

### 3.3 제스처 판정 (D-010)

**톡**: 펜을 댔다 뗀 획 중 접촉 시간 ≤ `T_tap`(180ms), 이동 거리 ≤ `D_move`(1.0mm)인 것.

**질문 제스처**: 아래를 모두 만족하면 질문으로 본다.

| # | 조건 | 기본값 | 이유 |
|---|------|--------|------|
| G1 | 입력이 펜이다 (`pointerType === "pen"`) | — | 손가락은 화면 이동·확대 전용 |
| G2 | 현재 도구가 펜 또는 연필이다 | — | 지우개·올가미·형광펜의 동작과 겹치지 않게 |
| G3 | 두 톡 사이(첫 톡 뗌 → 둘째 톡 댐) ≤ `T_gap` | 300ms | 「빠르게 두 번」 |
| G4 | 두 톡 위치 거리 ≤ `D_pair` | 3.0mm | 같은 자리 |
| G5 | 두 톡이 **같은 `Word`의 획 위**에 있다: 톡 위치에서 그 단어 획 경로까지 거리 ≤ 0.3h | — | 쌍점·말줄임표·마침표는 글자 사이나 뒤에 찍히므로 걸러진다 |
| G6 | 둘째 톡 뒤 `T_confirm` 안에 셋째 톡이 없다 | 250ms | 말줄임표처럼 세 번 찍는 점을 거른다 |
| G7 | 첫 톡이 직전 필기 획이 끝난 뒤 `T_burst` 이후에 시작했다 | 150ms | 쓰는 흐름 속의 점(ㅎ 꼭지, i 점)을 거른다 |

또는 톡 위치가 `AnswerBlock` 안이면 G5 대신 「답 영역 안」을, `FollowUpSlot` 안이면 「칸 안에 쓴 획 위」를 쓴다.

**필기감을 지키는 처리**

- 첫 톡은 판정을 기다리지 않고 곧바로 점으로 그린다. 상태는 「임시」다.
- 질문으로 판정되면 두 톡의 점을 지운다. 이 두 점은 실행 취소 기록에 남기지 않는다.
- 질문이 아니면 임시 점을 그대로 확정한다. 다음 획이 시작되거나 `T_gap`이 지나면 확정한다.
- 판정은 펜을 뗄 때(`pointerup`)만 하고, 계산은 상수 시간이다. 필기 입력 경로를 막지 않는다.

**설정**

- 「두 번 톡 질문」 켜기/끄기 (시험 볼 때, 남에게 보여 줄 때 끈다).
- 민감도 3단계: `T_gap` 250/300/400ms, `D_pair` 2/3/4mm.
- 대안 입력(선택): 갤럭시 S펜 측면 버튼을 누른 채 한 번 톡. 웹에서 S펜 버튼은 `buttons` 값으로 들어온다. Apple Pencil의 몸통 더블탭·쥐기는 웹에서 받을 수 없으므로 쓰지 않는다.

### 3.4 획 전처리

획마다 다음을 계산해 쪽 단위 공간 색인(줄 높이 크기의 격자 버킷)에 넣는다.

- 경계 상자, 몸통 구간(y 15–85 백분위), 길이, 시작·끝 시각
- 다음 획은 문장 찾기에서 뺀다.
  - 형광펜 획, `AnswerBlock` 위에 쓴 주석 획, 임시 톡 점
  - **그림 획**: 몸통 높이 > 2.5h, 또는 길이 > 8h이면서 시작·끝 거리 < 0.2×길이(닫힌 도형), 또는 그림 획과 이어진 묶음. 그림 옆 짧은 라벨 글씨는 그림 획에서 0.5h 이상 떨어져 있으면 글씨로 둔다.

### 3.5 줄 구성

**괘선·모눈 종이** (D-016)

- 획을 몸통 중심 y가 들어가는 줄 칸에 넣는다. `row = floor((y_core - y0) / p)`. 모눈은 사용자가 쓴 글씨 크기로 줄 간격을 추정한다(칸 1개 또는 2개).
- 몸통이 두 칸에 걸치면 더 많이 걸친 칸으로 넣는다.

**무지 종이**

1. 획을 몸통 중심 y로 정렬한다.
2. 앞에서부터 줄에 붙인다. 그 줄의 기준선(몸통 중심을 x에 대해 로버스트 선형 회귀한 직선)과 세로 거리가 0.6h 안이면 붙이고, 아니면 새 줄을 연다. 기준선 기울기로 비스듬한 줄을 처리한다.
3. 같은 높이에서 x 구간이 겹치지 않는 두 줄은 세로로 50% 이상 겹치면 합친다.
4. 애매한 획(위아래 줄 사이)은 **쓴 순서**로 정한다. 바로 앞이나 뒤에 1.5초 안에 쓴 획과 같은 줄로 넣는다.

**줄 안 나누기**

- 획을 x로 정렬하고 x 구간이 겹치는 것끼리 `GlyphCluster`로 묶는다.
- 묶음 사이 간격의 중앙값을 g라 할 때, 단어 간격 `τw = max(0.4h, 1.8g)`, 덩어리 간격 `τs = max(3h, 3τw)`.
- 간격 > τw이면 단어를 나누고, 간격 > τs이면 `Segment`를 나눈다.

**본문 열**

- 탭한 `Segment`의 왼쪽 끝을 열의 왼쪽 `x_L`로 둔다(같은 열에서 위아래 줄의 왼쪽 끝 중앙값으로 보정).
- 오른쪽 `x_R`은 괘선 종이면 오른쪽 여백선, 무지면 주변 ±10줄의 오른쪽 끝 95 백분위.

### 3.6 1단계: 후보 덩어리

목표: 인식하기 전에, 획 기하와 쓴 시간만으로 「질문이 들어 있을 만한 줄 덩어리」를 빠르게 고른다. 이 덩어리만 인식에 보내므로 비용이 작고, 0.1초 안에 점선으로 보여 줄 수 있다.

1. 시작점: 두 톡의 중점에서 가장 가까운 `Word`(앵커 단어)와 그 `Segment`, 줄 `L0`.
2. 위로: 바로 윗줄에서 `L0`의 열과 가로로 30% 이상 겹치는 `Segment`를 찾는다. 이어짐 점수 `C(윗줄, 아랫줄) ≥ θc`이면 덩어리에 넣고 한 줄 더 올라간다.
3. 아래로: 같은 방식으로 내려간다.
4. 최대 위로 3줄, 아래로 3줄까지만 본다.

**이어짐 점수** `C(u, d)` (u: 윗줄, d: 아랫줄)

| Feature | 조건 | Weight |
|---------|------|--------|
| `full(u)` | u의 오른쪽 끝 ≥ `x_R − 2h` (줄이 끝까지 차서 넘어갔다) | +1.0 |
| `align(d)` | `|d.x_left − x_L| ≤ 1h` (들여쓰기 없이 이어 쓴다) | +0.6 |
| `time(u,d)` | d의 첫 획 시작 − u의 마지막 획 끝 ≤ 5초 | +0.5 |
| `bullet(d)` | d가 목록 기호로 시작한다: 맨 앞 묶음이 0.6h 이하의 점·줄표, 동그라미 숫자 모양, 숫자+점 모양이고 뒤에 τw 이상 간격 | −1.5 |
| `indent(d)` | `d.x_left − x_L > 1.5h` | −1.0 |
| `vgap(u,d)` | 두 줄 사이 빈 줄이 있다(괘선) 또는 세로 간격 > 1.6 × 이 쪽의 줄 간격 중앙값(무지) | −2.0 |
| `endmark(u)` | u의 마지막 묶음이 0.4h 이하의 점 또는 물음표 모양이다 | −0.8 |
| `itemStart(u,d)` | u가 목록 기호로 시작하고 d가 그 기호 자리(`|d.x_left − u.x_left| ≤ 1h`)에서 시작한다. 내어쓰기로 이어 쓴 줄은 해당하지 않는다 | −1.0 |

기본 문턱 `θc = 0.5`. 가중치와 문턱은 §5의 데이터로 다시 맞춘다.

예 (흐름 시안 3단계): 「② 탄소 고정…」 줄은 `itemStart` 때문에, 「· 광합성 속도…」 줄은 `bullet`과 `time`(나중에 씀) 때문에 빠지고, 가운데 두 줄만 덩어리가 된다.

### 3.7 인식

**입력**: 덩어리의 줄마다 획을 회색조 띠 이미지로 그린다. 글자 높이 h를 32px로 맞추고, 띠를 세로로 쌓고, 왼쪽 여백에 줄 번호를 찍어 한 장으로 보낸다. 그림 획은 뺀다.

**출력 형식** (엔진 공통 인터페이스)

```ts
interface LineRecognition {
  lineIndex: number;
  text: string;            // 띄어쓰기 포함
  confidence?: number;     // 0..1, 엔진이 주면
  wordBoxes?: { text: string; strokeIds: string[] }[]; // 엔진이 주면
}
```

- v01 엔진은 Nodi와 같은 Gemini 비전이다. 줄 번호별 JSON으로 답하게 한다. 줄 단위 텍스트는 주지만 단어 위치는 주지 않는다.
- 단어 위치를 주는 엔진(예: MyScript)으로 바꿔도 이 인터페이스만 맞추면 된다.

**글자와 획 잇기** (`wordBoxes`가 없을 때)

1. 인식 텍스트를 띄어쓰기로 나눠 `Token` 목록을 만든다.
2. `Token` 수와 그 줄의 `Word` 수가 같으면 순서대로 1:1로 잇는다.
3. 다르면 글자 수 비례로 잇는다: 각 글자에 그 줄 너비를 글자 수 비율로 나눠 x 위치를 주고, `Token` 경계를 가장 가까운 단어 간격(없으면 `GlyphCluster` 간격)에 붙인다.
4. 그래서 모든 `Token`은 획 목록을 갖는다. 형광펜 표시와 범위 수정 손잡이가 이 획 목록을 쓴다.

**인식 신뢰도 낮음**: 엔진 신뢰도 < 0.5, 또는 글자 수와 `GlyphCluster` 수 차이가 50%를 넘으면 낮음으로 본다(§3.9의 확인 모드로 간다).

**캐시**: 줄 인식 결과를 그 줄 획 id 목록의 해시로 캐시한다. 그 줄의 획이 바뀌면 버린다. 같은 줄을 다시 묻거나 주변 문맥(§3.10)을 만들 때 재사용한다.

### 3.8 2단계: 문장 경계 점수

덩어리의 `Token`을 읽는 순서(줄 순서, 줄 안에서는 왼쪽부터)로 늘어놓고 `t1 … tn`이라 하자. 이웃한 두 토큰 사이 i마다 경계 점수를 계산한다.

```text
B(i) = Σ_k  w_k · f_k(i)        경계이면 B(i) ≥ θb (기본 0.9)
```

| k | Feature | 값 | Weight |
|---|---------|----|--------|
| 1 | `punct(t_i)` | t_i가 `. ? ! 。 ？ ！`로 끝나면 1, `…`이면 0.5. 숫자 안의 점(3.5), 괄호 안의 물음표는 0 | +1.2 |
| 2 | `ending(t_i)` | 한국어 종결어미로 끝나면: `-다 -요 -까 -니 -냐 -죠`는 1, 개조식 `-함 -임 -음 -됨`은 0.6 | +0.8 |
| 3 | `connective(t_i)` | 연결어미나 쉼표로 끝나면 1: `-고 -며 -는데 -지만 -면 -서 -거나 ,` (`-니까?`처럼 물음표가 붙으면 0) | −1.0 |
| 4 | `linebreak(i)` | t_i가 줄 끝, t_{i+1}이 다음 줄 처음이면 `1 − σ(C(u,d))`, 같은 줄이면 0 | +0.8 |
| 5 | `marker(t_{i+1})` | t_{i+1}이 목록 기호다: `• - * · ①…⑳ 1. 1) (1) 가. ㄱ. Q.` | +1.2 |
| 6 | `pause(i)` | 두 토큰 사이 쓰기 멈춤 Δt를 이 사용자의 단어 사이 멈춤 중앙값 m으로 정규화: `clip((Δt − m) / 4m, 0, 1)`. Δt > 60초(나중에 끼워 쓴 글)면 1 | +0.5 |
| 7 | `hgap(i)` | 같은 줄에서 간격 > τs | +1.0 |
| 8 | `starter(t_{i+1})` | 문장을 여는 말로 시작: `그런데 근데 그래서 그러나 하지만 따라서 그럼 그러면 즉 왜 어떻게` | +0.4 |

`σ`는 로지스틱 함수다. 가중치는 손으로 잡은 초기값이고, §5에서 경계 분류 데이터로 로지스틱 회귀를 학습해 바꾼다. 특징이 따로 떨어져 있어서 논문에서 특징별 기여도(제거 실험)를 잴 수 있다.

**문장 고르기**

1. 앵커 토큰 `a` = 두 톡의 중점을 획 목록 안에 담거나 가장 가까운 토큰.
2. `a`에서 왼쪽으로 가다가 처음 `B(i) ≥ θb`인 경계에서 멈추고, 오른쪽도 같다. 그 사이가 `QuestionSpan`이다.
3. 덩어리 끝에 닿으면 거기서 멈춘다(1단계가 이미 바깥을 잘랐다).

**예** (흐름 시안): `… 안 | 생긴다. | 근데 | 캘빈 | 회로는 ⏎ 빛을 | 직접 | … | 걸까?`

- 「생긴다.」 뒤: punct 1.2 + ending 0.8 + starter 0.4 = 2.4 → 경계
- 「회로는」 뒤(줄바꿈): 앞줄이 끝까지 찼고 다음 줄이 들여쓰기 없이 바로 이어 써서 `C` 높음 → linebreak ≈ 0.1, connective 아님 → 경계 아님
- 결과: 「근데 캘빈 회로는 빛을 직접 안 쓰는데 왜 밤에는 멈추는 걸까?」

**질문이 아닌 문장**: 고른 문장이 평서문이어도 그대로 묻는다. 답변 쪽에서 「이 내용을 설명해 달라」로 다룬다(§3.10).

### 3.9 범위 표시와 수정

| 시점 | 표시 |
|------|------|
| 판정 직후 (≤0.1초) | 1단계 덩어리를 연필 점선 상자로 |
| 인식 후 (≈1초) | 고른 문장을 줄마다 형광펜 띠로, 시작·끝에 손잡이. 옆에 「읽은 문장」 꼬리표 |
| 답 쓰는 중 | 꼬리표에 「답을 쓰는 중」과 「취소」 |
| 답 끝 | 형광펜 띠를 옅게 남기고 꼬리표를 닫는다 |

- **자동 질문**: 사용자 요청대로 범위가 정해지면 확인 없이 바로 묻는다.
- **확인 모드**: 인식 신뢰도가 낮거나(§3.7) 문장이 3토큰 이하 또는 40토큰 이상이면 바로 묻지 않고 꼬리표에 「이 문장이 맞나요?」와 「묻기」「범위 고치기」를 보여 준다.
- **손잡이 끌기**: 손잡이는 확인 모드에서 보인다. 토큰 경계에 붙고, 끌고 나면 꼬리표의 「묻기」로 새 범위를 보낸다. 자동 질문은 범위가 정해지자마자 답 자리를 만들기 때문에, 그 뒤에 범위를 고치려면 「취소」 후 다시 두 번 톡 한다.
- **취소**: 꼬리표의 「취소」를 누르면 표시를 닫고 진행 중인 요청도 취소한다. 원하지 않은 답이 나중에 끼어들어 필기를 밀어내면 안 되기 때문이다. 범위 밖에 계속 필기하는 것은 취소로 보지 않는다.
- **수동 범위**: 올가미로 획을 고르면 메뉴에 「이 부분 묻기」가 나온다. 자동 범위가 계속 틀릴 때의 탈출구다. 이때는 2단계를 건너뛰고 고른 획 전체를 질문으로 쓴다.

### 3.10 질문 문맥 만들기

답변 모델(v01: Gemini `GEMINI_ANSWER_MODEL`, D-017)에 보내는 내용

| 항목 | 내용 |
|------|------|
| `question` | `QuestionSpan`의 인식 텍스트 |
| `nearby` | 덩어리의 나머지 문장 + 위아래 3줄 (캐시에 있으면. 없으면 위아래는 생략) |
| `title` | 그 쪽 맨 위에서 글자가 가장 큰 줄 (예: 「3단원 광합성」) |
| `thread` | 이어 질문이면 같은 줄기의 이전 질문·답 최대 4쌍 |

답변 규칙(프롬프트 요구 사항)

- 한국어로, 노트에 들어갈 길이로 짧게 쓴다(3–5문장, 약 220자 이내). 더 필요하면 마지막에 「더 알려 줄까요?」 대신 사용자가 이어 질문하도록 둔다.
- 머리글·목록 같은 마크다운을 쓰지 않는다. 화학식·수식은 평문으로 쓴다(`CO2`, `6CO2 + 12H2O`). 아래첨자 표시는 화면에서 처리한다.
- 질문이 평서문이면 그 내용을 설명한다. 질문의 「이거」「그거」는 `nearby`와 `title`로 푼다.

### 3.11 답 자리 만들기 (D-004, D-012)

1. **끼우는 선** `y_ins` = `QuestionSpan` 마지막 줄의 아래 경계(괘선이면 그 줄 칸의 아래선).
2. **답 영역**: 가로는 질문 첫 줄 `Segment`의 왼쪽 `x_L`부터 `x_R`까지. 세로는 줄 단위.
3. **미리 잡기**: 답을 받기 전에 3줄을 먼저 비운다. 글이 늘어나면 한 줄씩 더 비우고(150ms 이동), 끝나면 남는 줄을 돌려준다. 이동은 줄 단위로만 일어나서 쓰는 동안 화면이 덜 흔들린다.
4. **밀기**: `y_ins` 아래에 위쪽 끝이 있는 모든 객체(획, 답, 이어 질문 칸)를 비운 줄 수 × p만큼 내린다. `y_ins`에 걸친 객체는 답 영역과 가로로 겹치면 통째로 내리고, 겹치지 않으면(예: 오른쪽 여백 그림) 그대로 둔다.
5. **질문 줄의 나머지**: 질문이 줄 중간에서 끝나고 같은 줄에 다른 글이 이어지면, 그 줄은 그대로 두고 답은 그 줄 아래에 들어간다.
6. **넘침**: 밀린 내용이 쪽 아래로 넘치면 쪽 높이를 줄 단위로 늘린다. 화면에는 이어 붙인 종이 이음선을 그린다(D-012).
7. **실행 취소**: 답 넣기와 밀기는 한 번의 실행 취소 단위다. 답을 쓰는 중에 실행 취소하면 요청도 취소한다.

`AnswerBlock`은 획이 아니라 텍스트 객체다. 그 위에 쓴 획(밑줄, 메모)은 답에 딸린 주석으로 묶여 함께 움직인다. 지우개로 답을 문지르면 답 전체가 지워지고(실행 취소 가능) 빈 줄은 남는다. 「빈 줄 정리」로 당길 수 있다.

### 3.12 이어 질문 (D-005, D-013)

1. 답을 두 번 톡(§3.3, 답 영역 조건) → 그 답 바로 아래에 2줄짜리 `FollowUpSlot`을 넣는다(§3.11과 같은 밀기).
2. 시작점이 칸 안에 있는 획은 칸에 속한다. 마지막 줄에 쓰기 시작하면 칸이 한 줄 늘어난다.
3. 칸 안의 글씨를 두 번 톡 하거나 「묻기」를 누르면 보낸다. 쓰기를 멈췄다고 저절로 보내지 않는다.
4. 칸에 쓴 글 전체가 질문이다. 2단계 문장 고르기는 하지 않는다.
5. 보내면 칸의 점선 테두리가 사라지고, 그 글씨가 질문이 되며, 답은 그 아래에 같은 `Thread`로 들어간다.
6. 칸에 아무것도 안 쓰고 쪽을 떠나면 칸을 지운다.
7. 같은 줄기의 질문과 답은 여백 표시(번호, 연필선 또는 각주선)로 이어 보인다. 모양은 디자인 시스템 §3.7.

### 3.13 충돌 처리

| 상황 | 처리 |
|------|------|
| 마침표·쌍점·말줄임표 | 글자 위가 아니므로(G5) 필기. 세 번 찍으면(G6) 필기 |
| ㅎ 꼭지, i 점 같은 쓰는 흐름 속의 점 | 한 번 톡이고 직전 획과 붙어 있으므로(G7) 필기 |
| 글자 위에 일부러 점 두 개 | 질문으로 잡힌다. 꼬리표의 「취소」로 되돌리고 두 점은 다시 그린다 |
| 지우개 도구에서 두 번 톡 | 지우개 동작만 (G2) |
| 형광펜 도구 | 질문 제스처 없음 (G2). 형광펜으로 칠한 줄도 펜으로 두 번 톡 하면 물을 수 있다 |
| 올가미 도구 | 질문 제스처 없음. 고른 뒤 「이 부분 묻기」 |
| 손가락 | 이동·확대. 두 손가락 톡은 실행 취소. 질문 없음 (G1) |
| 손바닥 | 펜이 닿아 있거나 펜이 근처에 있는 동안의 터치는 무시 |
| 이미 답을 받은 질문을 두 번 톡 | 꼬리표에 「이미 답한 질문」과 「다시 묻기」. 다시 물으면 질문 글씨를 다시 읽고 같은 답 자리에 새 답을 쓴다 |
| 질문 처리 중 그 질문 획을 고침 | 진행 중 요청 취소 → 0.6초 뒤 다시 인식 |
| 답을 받은 뒤 질문 획을 고침 | 답에 「질문이 바뀜」 표시와 「다시 묻기」. 저절로 다시 묻지 않는다 |
| 질문 두 개를 거의 동시에 | 각각 진행. 답 자리 만들기는 위쪽 질문부터 순서대로 처리(쪽 단위 배치 잠금) |
| 확대한 상태 | 제스처 기준은 화면 mm, 배치 기준은 h·p 배수라 그대로 동작 |
| 두 단 필기, 여백 메모 | `Segment` 나누기(τs)로 열이 갈린다. 답은 톡 한 열의 폭으로 |
| 오프라인 | 범위 표시까지만 하고 꼬리표에 「연결되면 물어볼게요」. v0.1은 자동으로 다시 보내지 않는다(닫고 다시 두 번 톡) |
| 「두 번 톡 질문」 꺼짐 | 모든 톡은 필기 |

### 3.15 연구용 기록

논문 평가를 위해 참여자 동의를 받은 경우에만 다음을 남긴다.

- 이벤트: 제스처 판정(성공·거부와 거부한 조건), 후보 덩어리, 인식 텍스트, 고른 범위, 손잡이 수정, 취소, 다시 묻기, 지연 시간
- 획 데이터는 범위 평가에 필요한 쪽만, 동의 범위 안에서 저장한다. 계정 정보와 분리한다.

| 대안 | 장점 | 버린 이유 |
|------|------|-----------|
| 줄 하나만 질문으로 | 단순, 빠름 | 줄 중간에서 시작하거나 두 줄에 걸친 문장을 못 다룬다 |
| 1단계(기하)만 | 인식 없이 빠름 | 한 줄 안의 두 문장을 못 가른다 |

| 범위 이미지를 통째로 LLM에 주고 「표시한 문장」을 고르게 하기 | 구현이 쉽다 | 범위가 매번 달라지고 획과 이어지지 않아 형광펜·손잡이를 못 그린다. 특징별 평가를 못 한다 |
| 올가미로만 범위 지정 | 정확하다 | 필기 흐름을 끊는다. 탈출구로만 둔다 |
| 길게 누르기 | 점과 덜 헷갈린다 | 느리고, 펜을 대고 생각하는 습관과 겹친다 |
| Apple Pencil 더블탭·쥐기 | 화면과 안 겹친다 | 웹에서 받을 수 없고 펜 모델마다 다르다 |

## 5. 검증 방법

**단위 시험**

- 합성 획 묶음(점, 쌍점, 말줄임표, ㅎ 꼭지, 글자 위 두 번 톡)으로 G1–G7을 하나씩 확인한다.
- 줄 구성: 괘선·무지, 기울어진 줄, 두 단, 그림 섞인 쪽 고정 자료로 `InkLine` 결과를 확인한다.
- 경계 점수: 인식 텍스트와 획을 고정한 자료로 `QuestionSpan`이 기대값과 같은지 확인한다.

**논문용 평가**

- 자료: 참여자가 태블릿으로 실제 과목 필기를 하고, 그 안에서 질문하고 싶은 문장을 두 번 톡 한다. 각 톡에 대해 정답 문장 범위를 사람이 표시한다. 종이 종류(괘선·모눈·무지)를 고르게 섞는다.
- 지표
  - 범위 완전 일치율 (토큰 단위)
  - 획 단위 IoU (예측 획 집합과 정답 획 집합)
  - 경계 F1 (모든 경계 후보에서의 분류 성능)
  - 오작동: 1,000획당 질문으로 잘못 잡힌 수, 의도한 두 번 톡을 놓친 비율
  - 지연: §3.14 구간별
- 비교 대상: (B1) 톡 한 줄만, (B2) 1단계 덩어리 전체, (B3) 인식 + 문장부호로만 자르기, (제안) 2단계 전체, (제안+학습) 가중치를 로지스틱 회귀로 학습
- 제거 실험: 특징 f1–f8과 1단계 특징을 하나씩 빼고 범위 완전 일치율 변화를 본다.
- 1차 목표: 범위 완전 일치율 ≥ 85%, 획 IoU ≥ 0.92, 오작동 ≤ 1,000획당 1회.

## 6. 남은 질문

- 인식 엔진: v01은 Gemini 비전으로 줄 텍스트만 받는다. 단어 위치를 주는 엔진(MyScript 등)이 범위 정확도와 비용에서 나은지 비교할지.
- 수식이 많은 과목(수학·물리)의 수식 인식을 v01에 넣을지.
- 영어·한국어 섞인 필기의 종결 판정 규칙을 어디까지 넣을지.
- 이어 질문 자동 보내기(멈춤 감지)를 설정으로 둘지 (D-013).
- 답 길이 상한(현재 약 220자)이 노트 사용에 맞는지.
