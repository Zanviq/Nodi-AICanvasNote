## 1. 목적과 범위

- 다루는 것: 무엇을 만드는지, Nodi에서 무엇을 빼고 무엇을 새로 하는지, v01 기능 범위, 필기감 요구, 화면 목록, 데이터와 시스템 구성의 큰 그림
- 다루지 않는 것: 두 번 톡 질문 알고리즘 세부(`1030_v01_handwriting-question-recognition.md`), 색·글꼴·컴포넌트 값(`1030_v01_design-system.md`)

## 2. 배경

[Nodi](https://github.com/Nodi-Laboratory/Nodi)는 선생님이 올린 교과서를 근거로, 학생이 무한 캔버스에서 묻고 AI 답을 개념 카드로 펼쳐 보는 교실용 학습 서비스였다. 이 프로젝트는 Nodi의 내용을 논문에 쓰기 위해, 프로그램을 축소하고 일부 기능을 개선한 별도 프로그램이다.

목표는 「AI가 들어간 캔버스」가 아니라 **진짜 노트 앱**이다. 사람은 대부분의 시간을 그냥 필기하는 데 쓰고, 궁금한 문장이 생기면 그 문장을 펜으로 두 번 톡 해서 묻는다. 답은 노트 안, 질문 바로 아래에 남는다.

## 3. 설계

### 3.1 대상과 사용 장면

- 대상: 태블릿과 펜으로 필기하는 학생(주로 고등학생·대학생). 역할 구분 없음(D-001).
- 장면: 수업을 들으며 필기하다가 「캘빈 회로는 왜 밤에 멈추지?」라고 적는다. 그 문장을 펜으로 톡톡 친다. 몇 초 뒤 그 아래에 답이 적혀 있다. 답의 한 부분이 더 궁금하면 답을 톡톡 쳐서 이어 묻는다. 수업이 끝나면 노트에는 내 필기와 AI 답이 구분되어 함께 남는다.

### 3.2 Nodi와 달라지는 것

| Area | Nodi | AI Canvas Note v01 |
|------|------|--------------------|
| 사용자 | 학생·선생님·관리자 | 개인 사용자 1종 (D-001) |
| 화면 공간 | 흰 점 격자 무한 캔버스(Excalidraw) | 쪽 단위 종이 노트(괘선·모눈·무지, D-016) |
| 질문 입력 | 아래쪽 채팅 입력창 + 손글씨 질문 | 입력창 없음. 필기 속 문장을 두 번 톡 (D-003) |
| 답 표시 | 열 단위로 배치되는 개념 카드, 곡선 연결선 | 질문 바로 아래 줄에 인쇄체로, 아래 필기를 밀어서 (D-004, D-012) |
| 이어 묻기 | 카드의 `parent_item_id` 트리 | 답을 두 번 톡 → 이어 질문 칸 → 아래로 이어진 답 (D-005) |
| 근거 자료 | 교과서 업로드, Document Parse, Qdrant RAG | v01에서 뺌 (D-015) |
| 도판·강의 클립·개념 지도·질문 코치 | 있음 | v01에서 뺌 |
| 선생님·관리자 콘솔 | 있음 | 없음 |
| 디자인 | 노드·카드, 연두 계열 강조색 | 종이·잉크·제본의 노트 디자인 (D-006) |
| 필기감 | Excalidraw 펜 | 압력·기울기·저지연을 직접 다루는 필기 엔진 (D-002) |

**개선(업그레이드)하는 것**

- 질문 범위를 사람이 정하지 않아도 되는 문장 범위 추정(두 번 톡).
- 실제 노트앱 수준의 필기감.
- 답과 필기의 출처 구분(인쇄체·전용 잉크색·여백 표시, D-011).

### 3.3 핵심 흐름

1. 노트를 열고 쓴다.
2. 궁금한 문장 위를 펜으로 두 번 톡 → 후보 범위(점선) → 문장 범위(형광펜)와 「읽은 문장」 → 자동으로 묻는다.
3. 답이 질문 아래 줄에 써진다. 아래 필기는 줄 단위로 밀린다.
4. 답을 두 번 톡 → 이어 질문 칸 → 쓰고 두 번 톡 또는 「묻기」 → 그 아래로 답이 이어진다.
5. 답 위에 밑줄·메모를 쓸 수 있다. 답을 지우거나, 질문을 고쳐 다시 물을 수 있다.

화면 흐름은 `mockups/1030_v01_mockup-flow-double-tap.html`.

### 3.6 필기감 요구 (D-002)

| 항목 | 목표 |
|------|------|
| 펜 → 화면 지연 | 웹 기준 1프레임 이내 표시를 목표로, 예측 점으로 체감 지연을 줄인다 |
| 입력 샘플 | `getCoalescedEvents()`로 120Hz 입력을 모두 쓴다 |
| 압력·기울기 | 펜 종류별 압력 곡선. 연필은 기울기로 굵기·농도 |
| 매끄럽게 | perfect-freehand 계열 보간. 떨림만 줄이고 글씨 모양은 바꾸지 않는다 |
| 손바닥 무시 | 펜이 닿아 있거나 가까이 있는 동안 터치 무시 |
| 화면 이동 | 손가락 두 개로 이동·확대. 펜으로는 화면을 움직이지 않는다 |
| 종이 질감 | 종이 결과 잉크 번짐을 은은하게. 필기 가독성을 해치지 않는다 |

### 3.7 데이터 모델 개요

```ts
type PaperKind = "ruled" | "grid" | "plain";

interface Notebook { id: string; title: string; paper: PaperKind; createdAt: string }
interface Page { id: string; notebookId: string; index: number; extraRows: number } // extraRows: 이어 붙인 줄 수 (D-012)
interface Stroke {
  id: string; pageId: string; tool: "pen" | "pencil" | "highlighter";
  color: string; width: number;
  points: { x: number; y: number; p: number; tx: number; ty: number; t: number }[];
  parentAnswerId?: string; slotId?: string;
}
interface Thread { id: string; pageId: string }
interface QuestionSpan { id: string; threadId: string; strokeIds: string[]; text: string; source: "double-tap" | "lasso" | "slot" }
interface AnswerBlock { id: string; threadId: string; questionId: string; text: string; x: number; y: number; rows: number; status: "streaming" | "done" | "stale" | "error" }
interface FollowUpSlot { id: string; threadId: string; afterAnswerId: string; y: number; rows: number }
```

`color`, `x`, `y` 같은 값은 저장 데이터다. 화면 코드의 색·크기는 디자인 토큰만 쓴다(`CLAUDE.md` §8).

### 3.8 시스템 구성 (D-008, 제안)

```text
[태블릿 브라우저 PWA]
  Next.js + React + TS
  필기 엔진: Canvas 2D + Pointer Events
  두 번 톡 판정·1단계 범위: 브라우저에서 (지연 때문)
        │  HTTPS (줄 이미지, 질문 문맥)       ▲ SSE (답 스트리밍)
        ▼                                      │
[FastAPI 백엔드 (Nodi에서 축소)]
  /recognize  → Gemini 비전 (줄 단위 텍스트)
  /answer     → Upstage solar-pro3 (스트리밍)
  노트·쪽·획 저장, 연구 기록
        │
        ▼
[PostgreSQL]
```

- 범위 추정 2단계(경계 점수)는 인식 결과를 받은 뒤 브라우저에서 계산한다. 서버 왕복을 한 번 줄이고, 획 데이터가 이미 브라우저에 있기 때문이다.
- API 키는 백엔드에만 둔다.

## 4. 대안과 선택 이유

| 대안 | 장점 | 단점 | 판단 |
|------|------|------|------|
| 웹 PWA (제안) | iPad·갤럭시 탭 한 코드, Nodi 재사용, 배포 쉬움 | 네이티브보다 필기 지연이 크다 | 논문 일정과 재사용을 우선 |
| iPadOS 네이티브(PencilKit) | 필기감 최고, Pencil 제스처 사용 가능 | 갤럭시 탭 불가, 새로 짜야 함 | 필기감이 결정적으로 부족하면 재검토 |
| Flutter | 두 플랫폼, 네이티브에 가까운 성능 | Nodi 재사용 불가, 팀 경험 | 보류 |

## 5. 검증 방법

- 시안 확인: `mockups/`의 세 시안으로 시각 방향을 고른다(D-014).
- 필기감: 실제 iPad·갤럭시 탭에서 펜 → 화면 지연을 고속 촬영(240fps)으로 측정해 기록한다. 같은 조건에서 GoodNotes 같은 기존 노트앱과 비교한다.
- 기능: 3.5의 포함 항목마다 작업 설계(`docs/work/`)에 확인 방법을 쓴다.
