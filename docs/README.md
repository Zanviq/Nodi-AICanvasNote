# docs

AI Canvas Note의 설계, 작업 설계, PR 기록, 조사 보고서를 모으는 공간이다. 문서를 쓰기 전에 그 폴더의 `README.md`를 먼저 읽고 양식을 그대로 지킨다.

## 폴더 지도

| Path | 용도 | 식별자 |
|------|------|--------|
| `design/` | 전반적인 설계와 설계 변경 기록. 결정 로그, 설계 묶음, 변경 설계서 | `DL`, `v{NN}`, 커밋 7자리 |
| `work/` | 새 개발 작업마다 그 작업만의 작은 설계 (전체 설계가 아님) | 없음 (브랜치 폴더로 구분) |
| `PR/` | PR 하나에 폴더 하나. PR 설명서와 리뷰 기록 | `PR{번호 3자리}` |
| `report/` | 사용자가 요청한 조사 보고서, 테스트 데이터·계정 문서 | 커밋 7자리 또는 `PR{번호 3자리}` |

문서끼리 충돌할 때의 우선순위는 루트 `CLAUDE.md` 3.2절을 따른다. (결정 로그가 가장 위)

## 공통 이름 규칙

```
MMDD_{식별자}_{문서-이름}.md
```

- `MMDD`: 한국 시간(KST) 기준 작성일. 이름의 날짜는 처음 만든 날로 고정하고, 내용을 고쳐도 바꾸지 않는다.
- `{문서-이름}`: 그 문서를 특정할 수 있는 이름. 소문자 영문 kebab-case 권장, 한글 허용, **공백 금지**.
- `{식별자}`: 아래 표에서 고르며, 각 폴더 README가 어느 것을 쓸지 정한다.

| 식별자 | 형식 | 언제 | 예 |
|--------|------|------|-----|
| 기준 커밋 | 짧은 해시 7자리 | 기본값. 문서가 기준으로 삼은 커밋 | `1002_a1b2c3d_mcp-sync-protocol.md` |
| PR 번호 | `PR` + 3자리 (모자라면 앞을 0으로, 1000번부터 그대로) | PR 문서, 특정 PR에 대한 보고서 | `0924_PR002_login-page.md`, `1201_PR1024_release-notes.md` |
| 버전 | `v` + 2자리 | 설계 묶음 폴더와 그 안의 문서 | `1030_v01_canvas-note/` |
| 결정 로그 | `DL` | 결정 로그 파일 | `1030_DL_decision-log.md` |
| 커밋 없음 | `init` | 저장소가 아직 없어 기준 커밋이 없을 때만 (커밋 식별자 대신) | `1030_init_ocr-engine-survey.md` |

- PR 번호를 3자리로 맞추면 폴더 목록이 PR 번호 순서대로 정렬된다.
- 본문이나 제목에서는 `PR47`처럼 번호 그대로 언급해도 된다. 이름만 반드시 3자리로 맞춘다.
- 예외: `work/`는 `work/{브랜치 이름}/MMDD_{문서-이름}.md` 형식이다. (`work/README.md`)

## 공통 작성 규칙

- 한국어(해라체)로 쓰고, 테이블 열 이름·API·코드 식별자는 영어로 쓴다.
- 양식에서 해당 없는 절은 지우지 말고 「해당 없음」이라고 쓴다.
- 양식을 바꿔야 하면 그 폴더 README부터 고친다.
- 새 문서 폴더를 만들면 아래 양식으로 그 폴더의 `README.md`를 함께 만든다.

## 새 문서 폴더 README 양식

```markdown
# {폴더 이름}

{이 공간의 용도를 한두 문장으로 쓴다.}

## 용도

- {여기에 두는 문서}
- {여기에 두지 않는 문서와 그 문서가 갈 곳}

## 이름 규칙

- 형식: `MMDD_{식별자}_{문서-이름}.md`
- 식별자: {이 폴더에서 쓰는 식별자와 이유}
- 예: `{예시 파일 이름}`

## 작성 규칙

- {이 폴더만의 추가 규칙. 없으면 「해당 없음」}

## 문서 양식

아래를 그대로 복사해 쓴다. 해당 없는 절은 지우지 말고 「해당 없음」이라고 쓴다.

(양식 본문을 markdown 코드 블록으로 넣는다)
```
